# CallMineAI — Next.js port

Deployment preparation: see [Contabo VPS handoff](deploy/CONTABO.md).
Production templates are in `deploy/`; copy and customize them on the server.
Keep this repository private. Real `.env`, uploads and database dumps are excluded.

A port of the Laravel 12 + Inertia CallMineAI application to **Next.js 15 (App Router) + Prisma + MySQL**.

The UI is unchanged. Every React page, layout and component was copied over from
`resources/js` and still renders exactly as it did under Inertia.

---

## Quick start

```bash
cd NextJS
cp .env.example .env          # then fill in DATABASE_URL, AUTH_SECRET and APP_KEY
npm install
npx prisma generate
npm run db:seed               # admin + client demo accounts, plans, locales, templates
npm run dev                   # http://localhost:3000

# in a second terminal — the dialer + scheduled tasks
npm run worker
```

Seeded logins (password `12345678`): `admin@spagreen.net` for `/admin`,
`client@spagreen.net` for `/app`.

The app reads the **same MySQL database** the Laravel app uses — no data migration
is needed. `prisma/schema.prisma` was generated by introspecting that schema
(`prisma db pull`), so all 85 tables map 1:1.

> **Copy `APP_KEY` from the Laravel `.env` verbatim.** SMTP passwords,
> payment-gateway credentials and `integration_settings` rows are encrypted with
> Laravel's AES payload format; `src/lib/crypt.js` reads and writes that same
> format, but only with the original key.

## How the port works

Three compatibility layers let 21k lines of UI move across untouched.

### 1. The Inertia shim — `src/lib/inertia.jsx`

The pages still `import { Head, Link, router, useForm, usePage } from '@inertiajs/react'`;
a codemod repointed that specifier at `@/lib/inertia`, which reimplements the API
on the App Router:

| Inertia | Next.js implementation |
| --- | --- |
| `usePage().props` | React context filled by a server component |
| `router.get(url, data)` | `useRouter().push()` with a query string |
| `router.post/put/patch/delete` | `fetch()` to a route handler |
| `useForm()` | same shape: `data`, `setData`, `errors`, `processing`, `transform`, `recentlySuccessful`, … |
| `Link` | `next/link` (GET) or a `fetch` submit (other verbs) |
| `Head` | syncs `document.title` |

A `422` reply populates `errors` exactly as Laravel validation did; a reply
carrying `{ redirect }` navigates, and `{ flash }` feeds `props.flash`.

### 2. `route()` — `src/lib/route.js` + `route-manifest.js`

Ziggy's global `route()` helper, backed by a manifest of all **328 named routes**
exported from `php artisan route:list`. Every `route('client.agents.edit', id)`
call in the UI resolves to the same URL it did before.

### 3. The `/api` mirror

Laravel served a page and its mutations from one URI (`GET /app/agents`,
`POST /app/agents`). The App Router cannot host a `page` and a `route` in one
segment, so the shim rewrites non-GET visits to the same path under `/api`:

```
GET  /app/agents          -> src/app/app/agents/page.jsx
POST /app/agents          -> src/app/api/app/agents/route.js
PUT  /app/agents/7        -> src/app/api/app/agents/[agent]/route.js
```

The mapping is mechanical, so no `route()` call in the UI had to change.

## Architectural mapping

| Laravel | Next.js |
| --- | --- |
| Eloquent model | Prisma model (`@@map` to the same table) |
| `Inertia::render($c, $props)` | `renderPage(Component, name, props)` in a server `page.jsx` |
| Controller action (GET) | `page.jsx` server component |
| Controller action (write) | `route.js` handler under `src/app/api/**` |
| `$request->validate()` | `validate(data, rules, { prisma })` — same rule strings |
| `redirect()->route()->with()` | `redirectTo(url, flash)` |
| `back()->with('error', …)` | `back({ error: … })` |
| `abort(403)` | `abort(403)` |
| Session guards `web` / `admin` | JWT cookies `cm_session` / `cm_admin` |
| `Hash::make` / `Hash::check` | `bcryptjs` (reads Laravel's `$2y$` hashes) |
| `Crypt::encryptString` | `src/lib/crypt.js` (identical payload format) |
| `RateLimiter` | `src/lib/rate-limit.js`, backed by the `cache` table |
| `Storage::disk('local')` | `src/lib/storage.js` → `storage/app` |
| `config('calling.engines')` | `config.calling.engines` in `src/lib/config.js` |
| SoftDeletes | explicit `deleted_at: null` filters (Prisma has no global scopes) |

### Tenancy and authorization

Tenant scoping stays **manual**, exactly as in the Laravel app — there is no
global scope. Every query filters on `client_id`, resolved once per request by
`resolveClientId()` (which also honours admin impersonation). Writes call
`assertOwned(record, clientId)` before touching a row.

Both RBAC systems are ported: admin permissions via `roles`/`permissions`, and
customer permissions via `client_roles`/`client_permissions` — including the
legacy rule that a client administrator, or a member with no assigned role, gets
`['*']`.

## Conventions when adding a route

A page:

```jsx
// src/app/app/<thing>/page.jsx
export const dynamic = 'force-dynamic';

export default async function Page({ searchParams }) {
    const { user, clientId } = await requireClientPage();
    const props = /* the array the controller passed to Inertia::render */;
    return renderPage(ThingIndex, 'client/Thing/Index', props, { url: '/app/thing' });
}
```

A mutation:

```js
// src/app/api/app/<thing>/route.js
export const POST = handler(async (request) => {
    const gate = await gateClient({ routeName: 'client.thing.store' });
    if (gate.response) return gate.response;

    const data = await validate(await readBody(request), rules(), { prisma });
    await prisma.thing.create({ data: { ...data, client_id: BigInt(gate.clientId) } });

    return back({ success: 'Thing created.' });
});
```

`handler()` turns a thrown `ValidationFailed` into a 422 and an `assertOwned`
failure into a 403, so handlers stay free of try/catch.

## Background work

The Laravel scheduler and queue worker become HTTP tasks the app runs itself:

| Task | Schedule | Endpoint |
| --- | --- | --- |
| Dispatch due outbound calls | every minute | `POST /api/cron/dispatch` |
| Recover calls with no terminal webhook | every 5 minutes | `POST /api/cron/reap-stuck` |
| Grant monthly plan credits | daily 02:00 | `POST /api/cron/grant-monthly` |
| Reconcile gateway subscriptions | daily 03:00 | `POST /api/cron/sync-subscriptions` |

All are guarded by `CRON_SECRET` (falling back to `AUTH_SECRET`) and take an
overlap lock in the `cache` table. `npm run worker` calls them on that schedule;
a hosted cron (Vercel Cron, systemd timer, crontab) can replace it by POSTing the
same URLs with an `X-Cron-Secret` header.
